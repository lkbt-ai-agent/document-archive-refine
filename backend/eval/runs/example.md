# 리포트 용어 설명

이 폴더의 `runs/<run_id>/report.md`를 읽는 데 쓰는 용어를 정리한다. 한 줄에 한 용어다.

## 기본 개념

- run: 케이스 전체를 앱에 한 번 돌려 채점한 실행이다.
- run_id: run을 식별하는 이름이다. `<UTC시각>-<git해시>` 형식이다.
- case(케이스): 질문 하나와 그 정답 문서 라벨을 묶은 시험 문항이다.
- mode(모드): 검색 방식이다. keyword, semantic, rag 중 하나다.
- config: 이 run이 켠 토글 조합이다. 예로 query_rewrite, title_match가 있다.
- baseline: 운영 동작 그대로 돌린 기준 config다.
- ablation(어블레이션): 기능을 하나씩 꺼서 점수 변화를 보는 실험이다.

## 검색 방식

- keyword(키워드 검색): 질의 단어를 본문과 글자 그대로 매칭한다.
- semantic(의미 검색): 질의를 임베딩해 벡터 유사도로 매칭한다.
- rag: 검색한 문서를 근거로 답변과 인용을 생성한다.
- 인용(citation): rag 답변이 근거로 단 출처 문서다. `[n]`으로 표기한다.

## 집계 지표

- pass_rate: 전체 케이스 중 통과한 비율이다.
- recall_at_5: 정답 문서가 상위 5개 안에 든 케이스 비율이다.
- recall_at_20: 정답 문서가 상위 20개 안에 든 케이스 비율이다.
- mean_rank: 정답을 찾은 경우 그 정답의 평균 순위다. 낮을수록 좋다. (1 이상 ~ 검색 깊이 만큼)
- retrieval_found: 키워드·의미 케이스 중 정답을 찾은 수 대 전체 수다. (찾은 수/전체 수)
- coverage_at_20: 정답이 여러 개일 때 상위 20개가 담은 정답 비율이다.
- citation_rate: rag가 인용을 단 비율이다. 존재 여부만 본다.
- citation_correct_rate: 그 인용이 실제 정답 문서였던 비율이다.
- rejection_rate: 정답 없는 함정 질문을 앱이 거부한 비율이다.
- by_mode(모드별 통과율): keyword, semantic, rag 각각의 통과율이다.
- by_failure_mode(실패 유형별 통과율): F1부터 F7 유형별 통과율이다.

## 실패 유형(F 코드)

- F1: 본문 심층 정보를 못 찾는 결함이다.
- F2: 약어나 표기 변이를 못 잡는 결함이다.
- F3: 올해나 작년 같은 시간 표현을 잘못 처리하는 결함이다.
- F4: 지역이나 범위 조건에서 정답을 빠뜨리는 결함이다.
- F5: 띄어쓰기나 형태 변이를 못 잡는 결함이다.
- F6: 정답 없는 질문을 거부하지 못하는 결함이다.
- F7: 카테고리 전체를 상위로 못 올리는 결함이다.

## 실패 케이스 표 컬럼

- id: 케이스 식별자다.
- mode: 그 케이스의 검색 방식이다.
- 유형: 그 케이스가 노린 실패 유형(F 코드)이다.
- 상태: pass, fail, error 중 하나다.
- 순위: 정답 문서의 순위다. 못 찾으면 n/a다.
- 인용: rag 인용이 정답이었는지다. 해당 없으면 n/a다.
- 거부: rag가 답변을 거부했는지다.
- note: 오류나 특이사항 메모다.

## ablation 비교 표

- config: 실험 조건 이름이다. baseline, no_rewrite, no_title_match가 있다.
- query_rewrite: 질의를 검색 전에 재작성하는 기능이다. 끄면 원문을 그대로 쓴다.
- title_match: 제목 매칭 토글이다. 로직은 별도 과제라 지금은 결과가 변하지 않는다.
- citation: 표에서 citation_rate를 줄인 이름이다.
- citation_ok: 표에서 citation_correct_rate를 줄인 이름이다.
