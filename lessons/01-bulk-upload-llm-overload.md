# Problem

- 사용자가 문서 약 52개를 한꺼번에 업로드했다.
- 인제스트 결과가 무너졌다. ready 5개, failed 41개, processing 6개로 끝났다.
- 워커 헬스는 `j_failed=47 j_ongoing=0 queued=0`을 기록했다.
- 실패 문서 40개는 `generating_meta` 단계에서 같은 에러를 남겼다. `Server error '500 Internal Server Error' for url 'http://localhost:8080/v1/chat/completions'`.
- processing 6개는 약 68분(age 4019~4065s) 동안 갱신 없이 멈췄고, 그중 1개는 `chunking` 60%로 화면에 떠 있었다.

# Cause

원인은 두 가지다. 1차는 LLM 서버 용량 초과이고, 2차는 취소 예외가 실패 처리를 우회한 결함이다.

### 0. 구성 한도 (사건 당시)

- arq 워커는 동시 잡 수를 명시하지 않아 arq 기본값 `max_jobs=10`으로 돈다. 워커는 인제스트 잡을 최대 10개까지 동시에 처리한다.
- 생성 LLM 서버(:8080)는 `-c 8192`로 뜨고 슬롯 4개로 나뉜다. 서버는 동시 요청 4개를 받고 슬롯당 실효 컨텍스트는 약 2048 토큰이다.
- 임베딩 LLM 서버(:8081)는 `--ctx-size 8192 --ubatch-size 8192`로 뜨고 병렬 슬롯을 지정하지 않아 기본 1슬롯으로 돈다.
- 메타 생성은 프롬프트 본문을 6000자로 자른다(`_MAX_CHARS=6000`). 서버는 출력을 `max_tokens=512`로 제한한다.
- 생성 워크플로의 다른 프롬프트는 별도 한도를 둔다. 예로 초안 brief는 4000자다.
- 한도가 어긋난다. 워커 10 동시 잡이 채팅 슬롯 4개를 초과하고, 6000자 한국어 프롬프트가 슬롯당 2048 토큰을 넘길 수 있다.

### 1. 생성 LLM(:8080) 컨텍스트·KV 캐시 고갈 (실패 41개)

- 대량 동시 업로드가 arq 워커의 병렬 잡을 폭증시켰다. `WorkerSettings`는 동시성을 제한하지 않아 arq 기본값(`max_jobs=10`)으로 잡을 동시에 돌렸다.
- 각 잡의 `generating_meta` 단계가 문서 본문(최대 `text[:6000]`자, 한국어 수천 토큰)을 `:8080`에 보냈다.
- 채팅 서버는 `-c 8192`로 떠 있고 슬롯 4개로 분할됐다(로그의 slot 0~3). 슬롯당 실효 컨텍스트는 약 2048 토큰이다.
- 다수의 큰 프롬프트가 동시에 들어오자 서버가 KV 캐시 공간을 확보하지 못했다. 로그가 이를 명시한다.
  - `W failed to find free space in the KV cache, retrying with smaller batch size ... n_batch=1`
  - `E srv update_slots: Context size has been exceeded. i = 1924`
  - `E srv send_error: error: Context size has been exceeded.`
- 서버는 해당 요청에 HTTP 500을 반환했고, 백엔드는 이를 문서 `error`로 기록했다.
- 나머지 실패 1개는 같은 과부하의 여파로 응답이 끊겼다. `Connection broken: IncompleteRead`.

### 2. 취소 예외가 실패 처리를 우회 (좀비 processing 6개)

- 경합으로 일부 잡이 arq 잡 타임아웃(기본 300s)을 넘겼다. 워커 로그가 `asyncio.wait_for` 경로의 `TimeoutError`와 `CancelledError`를 남겼다.
- `CancelledError`는 `BaseException`이라 파이프라인의 `except Exception`(실패 기록) 핸들러를 건너뛴다.
- 그 결과 잡은 종료됐는데도 문서 상태가 `failed`로 바뀌지 않고 직전 단계(`extracting`/`generating_meta`/`chunking`)에 그대로 남았다.
- 이 6개는 죽은 작업이다. arq `in-progress` 키가 없고 큐가 비었으며(`zcard=0`) 6개 모두 `arq:result:ingest:*` 결과 키를 가진다. 스스로 다시 진행하지 않는다.
- 화면의 60%는 프론트가 stage를 환산한 값이라 멈춰 보였을 뿐, 실제 청킹은 멈춘 상태였다.

### 곁가지

- OCR 경로가 별도 에러를 남겼다. `PaddleOCR 실패('>=' not supported between instances of 'list' and 'float') → Tesseract 폴백`. 폴백이 동작해 치명적이지 않으나 별도 버그다.

# Fix

해결책은 아직 적용하지 않았다. 수치는 §0 구성 한도를 기준으로 제안한다. 핵심 부등식은 둘이다. `max_jobs` 이하 슬롯 수, 그리고 프롬프트 토큰 더하기 출력 토큰 이하 슬롯당 컨텍스트(`-c` 나누기 슬롯 수)다.

- 막힌 데이터를 정리한다. 좀비 processing 6개를 `failed`로 정정하거나 재인제스트로 다시 큐잉하고, 실패 41개를 재처리한다.
- 권장안 A(처리량 유지): 채팅 서버를 `--parallel 4 -c 16384`로 띄운다. 슬롯당 컨텍스트가 2048에서 4096 토큰으로 는다. 워커는 `WorkerSettings.max_jobs=4`로 슬롯 4개에 맞춘다. 메타는 `_MAX_CHARS`를 6000에서 5000으로 줄여(약 3200 토큰) 출력 512와 합쳐도 4096 안에 둔다.
- 권장안 B(서버 변경 없이): 워커를 `max_jobs=2`로 낮춘다. 메타는 `_MAX_CHARS`를 6000에서 2400으로 줄여(약 1536 토큰) 현재 슬롯당 2048(=8192÷4) 안에 출력 512까지 맞춘다.
- 취소·타임아웃에도 실패를 기록한다. 파이프라인을 `try/finally`로 감싸 모든 종료 경로에서 상태를 `failed`로 종결하고 `CancelledError`를 명시적으로 처리한다(기존 D15 TODO와 같은 맥락).
- arq 잡 타임아웃을 명시한다. `WorkerSettings.job_timeout=900`(초)으로 올려 39쪽 PDF의 OCR·임베딩 시간을 덮는다(기본 300초가 과부하 시 초과됐다).

### 적용 후 모듈별 처리 한도

각 권장안을 적용했을 때 모듈별 한도는 아래와 같다. 토큰 추정은 사건 로그(6000자가 약 3845토큰)를 기준으로 환산한다.

| 항목 | 사건 당시 | 권장안 A | 권장안 B |
| --- | --- | --- | --- |
| 워커 동시 잡(`max_jobs`) | 10 | 4 | 2 |
| 채팅 슬롯(`--parallel`) | 4 | 4 | 4 |
| 채팅 컨텍스트(`-c`) | 8192 | 16384 | 8192 |
| 슬롯당 컨텍스트 | 2048 | 4096 | 2048 |
| 메타 프롬프트(`_MAX_CHARS`) | 6000자(약 3845토큰) | 5000자(약 3200토큰) | 2400자(약 1536토큰) |
| 프롬프트 더하기 출력(512) | 약 4357토큰 | 약 3712토큰 | 약 2048토큰 |
| 슬롯 적합 여부 | 초과(실패) | 적합(여유 약 384토큰) | 적합(여유 없음) |
| 실효 동시 LLM 처리 | 요청 10개가 슬롯 4개 경합 | 4건 | 2건(슬롯 4 중 2 사용) |
| 임베딩 서버(:8081) | 1슬롯, ctx 8192 | 변경 없음 | 변경 없음 |
| 잡 타임아웃 | 300초(기본) | 900초 | 900초 |

- 권장안 A는 처리량(동시 4건)을 유지하고 채팅 메모리를 더 쓴다. 슬롯당 컨텍스트가 4096이라 프롬프트가 여유를 가진다.
- 권장안 B는 서버 설정을 안 바꾸고 동시성·프롬프트를 줄인다. 슬롯당 2048에 프롬프트와 출력이 정확히 맞아 여유가 없다.
- 두 안 모두 워커 동시 잡을 슬롯 수 이하로 맞춰 KV 캐시 경합을 없앤다.

# Prevention

- 불변식 1을 지킨다. 워커 `max_jobs`는 채팅 슬롯 수(`--parallel`) 이하로 둔다. 현재 둘 다 4로 맞춘다. 한쪽을 올리면 다른 쪽도 같이 올린다.
- 불변식 2를 지킨다. 메타 프롬프트 토큰에 출력 `max_tokens`(512)를 더한 값이 슬롯당 컨텍스트(`-c` 나누기 `--parallel`) 이하여야 한다. 슬롯 4096 토큰 기준 프롬프트는 약 3584 토큰(약 5500자) 이하로 둔다.
- 잡을 끝내는 모든 경로에서 문서 상태를 종결 상태로 만든다. 정상·예외·취소·타임아웃을 모두 덮는다(`BaseException` 우회 주의). `job_timeout`은 900초로 명시한다.
- 대량 업로드 시 동시성을 올리지 않는다. 업로드 규모와 무관하게 `max_jobs`로 직렬화하고, 한 번에 수십 건을 넣기 전 소량으로 한도를 확인한다.
