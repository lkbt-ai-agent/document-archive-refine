# 03. 검색 정확도 테스트 케이스 생성 방법론

등록 문서와 크롤러 데이터로 검색 정확도를 낮추는 결함을 잡아내는 한국어 테스트 케이스를 어떻게 설계하는지 정의한다.

---

## 1. 개요

- 방법론은 결함 주도 설계를 채택한다. 방법론은 알려진 실패 유형마다 그 유형을 유발하는 케이스를 만든다.
- 방법론은 정답을 코퍼스와 manifest에서 역으로 끌어내 구성 단계에서 보장한다.
- 방법론은 질문을 개인부터 사내까지의 페르소나 자연어로 써서 구어, 시간어, 지명 표현을 주입한다.
- 방법론은 모드별 기대 동작을 분리해 키워드의 한계와 의미, RAG의 책임을 대비한다.
- 평가는 Recall@5/@20과 인용 이진 체크에 실패 유형별 통과율을 더한다(§9).

---

## 2. 정답 출처와 식별자

- 방법론은 크롤러 `manifest.jsonl`(`post_id`, `title`, `sha256`, `source_url`)을 정답 라벨의 1차 출처로 쓴다([02-test-data-crawler/00] §2.2).
- 방법론은 정답을 안정 식별자(`sha256` 또는 `source_id`+`post_id`)로 고정한다. `display_filename`은 바뀌므로 라벨로 쓰지 않는다.
- 출처가 도메인을 가른다. `sh`와 `lh`는 청약이고 개인 페르소나의 근거다. `mss`는 정부 사업이고 사내 페르소나의 근거다.

---

## 3. 실패 유형 분류 (defect taxonomy)

| ID | 이름 | 설명 | 대상 모드 |
| -- | ---- | ---- | --------- |
| F1 | 희소 코퍼스 점수 저하 | 정답 키워드가 청크 본문에 드물어 score가 낮고 순위가 밀린다. | 키워드, 의미 |
| F2 | 제목어 미반영 | 검색이 제목, 파일명 필드를 보지 않아 제목에만 있는 핵심어를 놓친다. | 키워드, 의미 |
| F3 | 시간어 미해석 | 검색이 "올해, 작년, 지금, 이번 달" 같은 상대 시간어를 날짜 범위로 환산하지 못한다. | RAG |
| F4 | 지명 포함관계 불일치 | 검색이 질문의 상위 행정구역("경기")과 문서의 하위 행정구역("화성시")을 잇지 못한다. | 의미, RAG |
| F5 | 한국어 형태 변이 | 조사, 어미, 띄어쓰기, 약어, 동의어 차이가 정확 매칭을 조용히 실패시킨다. | 키워드, 의미 |
| F6 | 환각, 오근거 | 모델이 코퍼스에 없는 질문에 답을 지어내거나 무관 문서를 인용한다. | RAG |
| F7 | 정밀도 저하 | 유사 공고가 많아 검색이 정답 대신 distractor를 상위로 올린다. | 키워드, 의미, RAG |

- F1과 F2는 관찰 1(데이터가 적어 score가 낮고 제목어가 안 잡힘)을 분해한다.
- F3과 F4는 관찰 2(시간어와 한국어 단어 인지율 저하)를 분해한다.
- F5, F6, F7은 두 관찰을 일반화하며 함께 점검할 인접 결함이다.

---

## 4. 케이스 스키마

- 방법론은 케이스를 JSONL 1행 1건으로 저장하고, CI가 이 픽스처를 결정적으로 읽는다.

```jsonc
{
  "id": "F4-region-001",
  "persona": "개인",                       // 개인 | 사내
  "mode": "rag",                            // keyword | semantic | rag
  "failure_modes": ["F4"],                 // §3 분류, 한 케이스가 여럿 가질 수 있음
  "question": "경기에 올해 올라온 행복주택 청약 있어?",
  "answer_doc_ids": ["lh:sha256:abc..."],  // 안정 식별자(§2)
  "expected": "화성시 행복주택 공고를 상위에 반환",
  "difficulty": "hard",                     // easy | medium | hard
  "notes": "문서는 화성시만 언급, 질문은 상위 행정구역 경기 사용"
}
```

## 5. 질문 생성

### 5.1 문서 역생성

- 설계자는 정답 문서에서 변별 사실을 뽑아, 그 사실만이 답이 되는 질문을 쓴다. 이 경로는 정답을 구성 단계에서 보장한다.
- 예: `mss`의 "2026년 소상공인 고용보험료 지원사업" 공고에서 "소상공인 고용보험료를 지원하는 2026년 사업이 뭐야?"를 만든다.

### 5.2 페르소나 자연어

- 설계자는 페르소나가 실제로 던질 구어체 질문을 쓰고 manifest로 정답을 라벨링한다. 이 경로는 구어, 시간어, 지명 표현을 주입한다.
- 개인 페르소나(청약 신청자)는 `sh`, `lh`를 겨냥해 지역, 주택유형, 시기를 구어로 말한다. 예: "경기에 요즘 행복주택 청약 뜬 거 있나?".
- 사내 페르소나(지원사업 담당자)는 `mss`를 겨냥해 지원 대상, 자격, 마감을 업무 어투로 말한다.

---

## 6. 케이스 설계 기법

### 6.1 최소 대조쌍 (minimal pairs)

- 설계자는 한 베이스 질문에서 한 변수만 바꿔 무엇이 검색을 깨는지 격리한다.
- 변수는 시간어 유무, 지명 상위어와 하위어, 약어와 정식명, 띄어쓰기, 조사다.
- 예: "화성 행복주택"과 "경기 행복주택" 쌍은 F4를, "올해" 유무 쌍은 F3을 격리한다.

### 6.2 지명 포함관계 기준표 (F4)

- 방법론은 시도와 시군구의 포함관계 표를 정답 확장 근거로 둔다(예: "경기"가 "화성시"를 포함).
- 문서가 하위 구역만 언급해도, 방법론은 그 문서를 상위 구역 질문의 정답으로 인정한다.

### 6.3 부정과 distractor

- 방법론은 코퍼스에 답이 없는 질문을 두고, 시스템이 "찾을 수 없습니다"로 거부하기를 기대한다(F6).
- 방법론은 유사 공고를 distractor로 두고, 검색이 정답을 그 위에 올리기를 기대한다(F7).

---

## 7. 모드별 기대 동작

- 키워드: 검색은 정확 토큰을 재현한다. 동의어와 지명 포함관계에서 키워드는 실패가 기대값이며, 케이스는 그 실패를 결함 근거로 기록한다.
- 의미: 검색은 패러프레이즈와 동의어를 재현한다.
- RAG: 시스템은 시간 필터를 환산하고 정답 문서를 인용하며 충실히 답한다. 근거가 없으면 "찾을 수 없습니다"로 답한다.

---

## 8. 수정 검증 ablation

- 방법론은 같은 케이스에서 검색 단계의 조건만 켜고 끄며, 어떤 수정이 점수를 올렸는지 순위와 Recall@K로 분리한다(§9).
- 방법론은 Hybrid, RRF, Reranker를 대상에서 뺀다(MVP 미채택, [01-mvp-research/02] §2, §3).
- 제목 매칭 ablation(F2): 현재 검색은 청크 본문만 보므로, 핵심어가 제목에만 있으면 정답을 놓친다. 설계자는 제목에만 변별어가 있는 문서로 네 조건을 비교한다.

| 조건 | 제목 매칭 | 쿼리 재작성 | 기대 |
| ---- | --------- | ----------- | ---- |
| baseline | 끔 | 끔 | 정답 순위가 낮거나 누락된다(F2 재현). |
| 제목 매칭 | 켬 | 끔 | 정답 순위가 오른다. |
| 재작성 | 끔 | 켬 | 효과가 제한적이다(본문에 변별어 없음). |
| 둘 다 | 켬 | 켬 | 정답 순위가 가장 높다. |

- 제목 매칭은 미구현 제안이라 사전 검증용 픽스처로 둔다. 쿼리 재작성은 채택 기능이라 실제 단계를 토글한다([01-mvp-research/02] §4).

---

## 9. 지표와 게이트

- 전역 지표는 Recall@5/@20과 인용 존재 이진 체크다([01-mvp-research/02] §6).
- Recall@K는 정답이 상위 K개에 드는 비율이고 정답 doc_id만 필요하다. `@20`은 높은데 `@5`가 낮으면 정답이 후보에는 있으나 순위가 밀린 것이다(리랭커 신호, [01-mvp-research/02] §3).
- 인용 이진 체크는 답변에 `[n]`이 하나라도 달렸는지를 0/1로 본다. 환각 억제만 싸게 확인하고 인용, 답의 정확성은 안 본다(LLM judge와 Ragas는 MVP 이후).
- 추가 지표는 실패 유형별 통과율, 평균 순위, 부정 케이스 거부율이다.
- CI는 이 지표를 결정적으로 측정한다. 라벨이 안정 식별자라 코퍼스가 늘어도 재현된다.

---

## 10. 규모, 층화, 유지보수

- 방법론은 베이스 케이스 약 50개를 출처(`sh`, `lh`, `mss`), 페르소나, 실패 유형으로 층화한다([01-mvp-research/02] §6).
- 방법론은 어려운 케이스를 `difficulty`로 분리해 평균에 묻히지 않게 한다.
- 픽스처는 정답을 manifest 식별자에 묶어 문서 삭제, 재적재에도 라벨을 유지한다.
- 새 결함이 보고되면 설계자는 §3에 유형을 추가하고 케이스를 늘린다.

---

## 11. 역할 분담

- "설계자"는 사람과 에이전트의 분담이다. 에이전트가 손일을 하고 사람이 결과의 신뢰를 보증한다.
- 에이전트는 문서 선택, 변별 사실 추출, 질문 생성(§5), 역생성 정답 라벨링, 대조쌍과 지명표와 부정 케이스(§6), 픽스처 작성과 평가 실행(§4, §9)을 맡는다.
- 사람은 정답 라벨과 그 완결성을 승인한다. 좁은 정답 집합은 정상 검색을 거짓 실패로 만든다.
- 사람은 기대 동작의 정의를 결정하고(예: "경기 청약"의 정답 범위), 어려운 케이스에 실제 질문을 투입하며, 실패 유형과 우선순위를 정한다.
- 자기참조 편향: 에이전트 생성 질문은 모델 취향으로 치우쳐 거친 한국어(오탈자, 조각, 약어)를 과소표현한다. 따라서 사람의 현실성 투입이 F4와 F5의 품질을 좌우한다.

## 12. 용어

- ablation: 한 조건만 켜고 끄며 그 요소의 효과를 분리하는 실험이다.
- defect taxonomy(결함 분류): 실패를 유형별로 묶은 표이다(§3).
- failure mode(실패 유형): 시스템이 깨지는 한 가지 방식이다.
- ground truth(정답 라벨): 사람이 미리 확정한 정답 기준값이다.
- minimal pairs(최소 대조쌍): 한 변수만 다른 두 입력으로 결과 변화를 짚는 기법이다(§6.1).
- distractor: 정답과 비슷해 헷갈리게 만드는 오답 후보 문서이다.
- false negative(거짓 실패): 사실은 맞는데 틀린 것으로 잘못 판정된 경우이다.
- precision(정밀도): 가져온 결과 중 진짜 정답의 비율이다.
- stratified sampling(층화 표집): 출처, 유형별 비율을 맞춰 고르게 뽑는 표집이다(§10).
- self-reference bias(자기참조 편향): LLM이 만든 데이터가 그 모델 취향으로 치우치는 현상이다(§11).
- 문서 역생성(back-generation): 정답 문서에서 거꾸로 질문을 만들어 정답을 보장하는 방식이다(§5.1).
- LLM judge: LLM에게 답 품질을 채점시키는 평가 방식이다. 비결정적이라 MVP에서 제외한다.
- Ragas, faithfulness: RAG 답변의 충실도(faithfulness) 등을 재는 평가 도구이다.
- query rewrite(쿼리 재작성): 사용자 질문을 검색에 맞게 다듬는 단계이다.
