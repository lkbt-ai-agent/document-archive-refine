# 01. 테스트 데이터 소스 확장 후보

크롤러가 수집할 추가 공개 사이트를 카테고리별로 제안하고, 어떤 인제스트 경로를 자극하는지 기준으로 MVP 우선순위를 정한다. 크롤러 설계 본문은 [00](./00-design.md)을 따른다.

---

## 1. 전제: 진짜 사문서는 공개 대상이 없다

- 실제 영수증과 계약서는 개인정보이다. 공개 게시판에 원본이 존재하지 않는다.
- 따라서 본 MVP는 공개 대체물을 수집한다.
- 공개 대체물은 표준계약서 양식, 공공 서식, 공고 PDF, 공개 OCR 데이터셋이다.

---

## 2. 포맷 제약 재확인

- 한국 공공 문서는 HWP/HWPX 형식이 다수이다.
- 앱 인제스트는 HWP/HWPX를 지원하지 않는다([01-mvp-research/01 §1], [docs/architecture/04-data/documents-schema.md] §1).
- 따라서 각 사이트의 `allowed_suffixes`로 PDF(및 이미지)만 통과시킨다([00 §1.1]).
- HWP만 제공하는 첨부는 건너뛴다. 이 점이 사이트별 확장자 화이트리스트의 또 다른 근거이다.

---

## 3. 후보 사이트(카테고리별)

| 카테고리 | 사이트 | 수집 대상 | 공개/로그인 | 포맷 | 페치 전략 | 판정 |
| -------- | ------ | --------- | ----------- | ---- | --------- | ---- |
| 계약서 | 공정거래위원회 표준계약서 | 표준가맹·표준하도급·표준약관 양식 | 무로그인 | HWP/PDF 혼재 | HTTP(eGovFrame, SH 재사용) | MVP 추가 권장 |
| 계약서 | 고용노동부 표준근로계약서 | 표준근로계약서 7종(일반·기간제·단시간·건설일용 등) | 무로그인 | HWP+PDF | HTTP | 2순위 |
| 계약서 | 한국저작권위원회 표준계약서 | 저작권 분야 표준계약서 서식 | 무로그인 | PDF/HWP | HTTP | 선택 |
| 공적 문서 | 대한민국 전자관보(gwanbo.go.kr) | 일자별 관보 PDF | 무로그인 | PDF(디지털 텍스트) | HTTP 또는 브라우저 | MVP 추가 권장 |
| 공고(보유) | SH, LH | 청약공고 PDF | 무로그인 | PDF | [00 §6] 참조 | 구현 대상 |
| 영수증 | AI Hub 영수증/OCR 데이터셋 | 영수증·문서 이미지+주석 | 다운로드 승인(로그인/신청) 필요 | 이미지 | 자동 크롤링 부적합 | 수동 취득(§6) |

- "공개/로그인"과 "포맷"은 검색 시점(2026-06) 관찰값이다. 구현 전 재확인한다.

---

## 4. MVP 우선순위(권장)

1. 공정거래위원회 표준계약서를 먼저 추가한다(계약서 카테고리).
   - 공정위 게시판은 eGovFrame 계열이라 SH의 HTTP 전략과 파서를 대부분 재사용한다([00 §6.1]).
   - 추가 구현 비용이 후보 중 가장 낮다.
2. 대한민국 전자관보를 다음으로 추가한다(공적 문서 카테고리).
   - 관보는 깨끗한 디지털 텍스트 PDF를 풍부하게 제공한다.
   - 이 데이터는 pypdf 텍스트 추출 경로([01-mvp-research/01 §2.1])를 넓게 검증한다.
- 2순위로 고용노동부 표준근로계약서를 더해 계약서 다양성을 보강한다.

---

## 5. 인제스트 경로 커버리지(왜 이 조합인가)

- 각 테스트 데이터는 앱 인제스트의 서로 다른 경로를 자극한다.

| 테스트 데이터 | 자극하는 인제스트 경로 |
| ------------- | ---------------------- |
| 관보·표준계약서 PDF(디지털 텍스트) | pypdf 텍스트 추출([01-mvp-research/01 §2.1]) |
| 청약공고·스캔 PDF/이미지 | OCR 경로(PaddleOCR/Tesseract, [01-mvp-research/01 §3]) |
| 영수증 이미지(공개 데이터셋, 수동) | OCR + 메타 생성([01-mvp-research/01 §3], §4) |
| TXT/MD(현재 후보엔 적음) | 인코딩 감지 경로([01-mvp-research/01 §2.3]) |

- TXT/MD는 현재 후보 사이트에서 확보가 어렵다. 별도 확보 또는 생성은 추후 과제이다.

---

## 6. 영수증 처리 방침(MVP)

- 본 MVP는 영수증 자동 크롤링을 채택하지 않는다.
- 사유는 두 가지이다.
  - 실제 영수증의 공개 원본이 없다(§1).
  - AI Hub 데이터셋은 다운로드 승인 절차를 요구해 무인 크롤링에 맞지 않는다.
- 대안 1: AI Hub 한국어 영수증/문서 OCR 데이터셋을 수동 다운로드해 `sample-datas/receipt/`에 수기 적재한다.
- 대안 2: 영수증 양식(템플릿) PDF를 공공 서식에서 받아 OCR 경로 입력으로 쓴다.
- 자동화는 데이터셋 이용약관 확인 후 phase-2로 미룬다.

---

## 7. 새 출처 적용 방법(추상화 재사용)

- 각 후보는 `BaseSource` 하위 클래스 하나로 추가한다([00 §3.1], [00 §4]).
- 공정위·고용부·저작권위·관보는 eGovFrame 또는 정적 게시판 계열이라 SH의 HTTP 전략과 파서를 대부분 재사용한다.
- 사이트마다 `source_id`, `allowed_suffixes`, `params_model`, `is_target_file`만 새로 정의한다.
- 이 구조 덕분에 출처 추가가 공통 파이프라인을 건드리지 않는다.
