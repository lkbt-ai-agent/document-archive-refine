## A. 인용 번호 재정렬
- [x] A1 `ask`가 생성된 답변에서 실제 인용된 `[n]`을 첫 등장 순서로 모은다.
- [x] A2 `ask`가 모은 인용 번호를 1부터 차례로 다시 매기는 매핑을 만든다.
- [x] A3 `ask`가 답변 텍스트의 `[n]`과 `citations`의 `n`을 같은 매핑으로 함께 바꾼다.
- [x] A4 `ask`가 인용되지 않은 청크를 `citations`에서 제외한다(번호 연속 보장).
- [x] A5 배경 메모: 현재 `n`은 검색 순위 위치라 3, 5처럼 보인다(이 절이 그 원인을 없앤다).

## B. 인용 근거 청크 표시
- [x] B1 `Citation` 스키마가 인용 청크 본문 `content`를 포함한다.
- [x] B2 `ask`가 각 인용에 해당 청크 본문을 채운다(검색 결과 `rows`의 본문 재사용, A의 재번호와 정합).
- [x] B3 프론트 `dto`·`map`·`types`가 `citation.content`를 싣는다.
- [x] B4 `CitationCard`가 청크 본문을 접고 펼치는 행으로 보여준다(디자인 `design/search-grouped` 4안 화살표 토글, 첫 항목 펼침 참고).
- [x] B5 청크 본문 표시가 줄바꿈 보존과 길이 처리를 4안 `ChunkBody` 규칙에 맞춘다.

## C. 스트리밍 응답
- [x] C1 배경: 총 처리 시간은 거의 같으나 첫 토큰까지 시간이 줄어 사용자 체감이 빨라진다. 현재는 파싱·검색·전체 생성을 모두 기다린 뒤 한 번에 표시한다.

### C-1. 로딩 화면 프로토타입 (먼저)
- [x] C2 `app/design/rag-streaming/page.tsx` 프로토타입이 스트리밍 로딩 3단계를 시안화한다(상단 세그먼트로 단계 전환).
- [x] C3 대기 단계(TTFT, 첫 토큰 전)가 빈 화면 대신 답변 형태 스켈레톤 카드와 진행 단계 표시(질의 분석·문서 검색·답변 생성)를 보여준다.
- [x] C4 스트리밍 단계가 점진 텍스트와 깜빡이는 커서를 보여주고 인용은 스켈레톤으로 자리만 잡는다.
- [x] C5 생성 중에 "중지" 버튼을 노출하고 답변 영역에 `aria-live`를 둔다.
- [x] C6 완료 단계가 전체 답변과 인용 카드(근거 청크 펼침)를 확정해 보여준다.
- [x] C7 사용자가 프로토타입을 승인하기 전에는 아래 실제 스트리밍 배선(C8~)에 착수하지 않는다.
- 근거: 스트리밍 로딩 UX 패턴(TTFT 갭 스켈레톤, 첫 토큰 후 타이핑 커서, 완료 시 인용 확정, `aria-live`)은 웹 조사로 확인한다(prompt-kit text-shimmer, Chrome AI render-llm-responses 등).

### C-2. 실제 스트리밍 배선 (프로토타입 승인 후)
- [x] C8 `LlamaCppLLM`이 생성 스트리밍(`stream=true`, SSE)을 지원하는 메서드를 제공한다.
- [x] C9 백엔드가 스트리밍 ask 엔드포인트(SSE)를 제공한다(파싱·임베딩·검색 후 생성 토큰을 흘려보낸다).
- [x] C10 스트리밍 경로가 생성 완료 후 최종 이벤트로 인용(재번호·근거 본문 포함)을 보낸다.
- [x] C11 프론트가 스트림을 소비해 승인된 프로토타입대로 답변을 점진 렌더하고 완료 이벤트에서 인용을 확정한다.
- [x] C12 진행 중에는 원 번호를 보이고 완료 시 재번호로 확정하거나, 완료 전까지 인용 표식을 비활성으로 둔다(번호 흔들림 최소화 방식을 택한다).
- [x] C13 비스트리밍 `POST /search/ask`는 폴백으로 유지한다.
