# 검색 & RAG 프론트엔드

- 셸/레이아웃은 `frontend.md`. 도메인 정의는 `search-and-rag.md`, API는 `search-backend.md`.
- 검색(retrieval)과 rag(QA)는 SearchBar 진입을 공유하되, 출력물이 달라 본문 렌더가 갈린다.

## 1. 검색 진입과 모드 선택
- AppHeader의 SearchBar 옆에 shadcn DropdownMenu 버튼(라벨 "검색...")을 둔다.
- 버튼 클릭 또는 SearchBar에서 Enter 시 키워드/의미/rag 드롭다운 메뉴를 띄운다.
- 메뉴에서 모드를 고르면 현재 입력값으로 그 모드의 검색을 실행한다(`/search?q=&mode=`로 이동, §4).
- 모드별 호출: 키워드/의미는 `POST /search`, rag는 `POST /search/ask`(search-backend.md).
- 제출 질의와 선택 모드는 URL이 보관한다(§5). 검색 타입 정의는 search-and-rag.md §2.

## 2. SearchBar 입력
- textarea 기반 입력. 강제개행(Shift+Enter)마다 일정 단계 높이만큼 늘어나는 stepped auto-grow로 디자인한다.
- Enter는 모드 드롭다운을 띄우는 트리거, Shift+Enter는 줄바꿈으로 분리한다.
- 한글 IME 조합 중 Enter는 무시한다(`isComposing` 가드).
- 최대 높이에 도달하면 그 안에서 스크롤한다.
- `≥md`에서 SearchBar를 헤더 중앙에 정렬한다.
- 모바일은 포커스 시 다른 헤더 요소를 가리고 전체 폭을 차지하며, blur 시 한 줄로 접힌다.

## 3. 결과 렌더 (본문 화면)
- 결과는 다이얼로그가 아니라 Center 본문 화면에 렌더하며, 조회(목록) 화면을 검색 결과 화면으로 전환한다.
- 키워드/의미: 본문 화면에 로딩을 먼저 표시하고 검색 결과 리스트를 반환한다.
- rag: `POST /search/ask/stream`(SSE)을 소비해 답변을 점진 렌더한다. 단계는 대기(TTFT, 첫 토큰 전)·스트리밍·완료다. 대기 단계는 빈 화면 대신 답변 형태 스켈레톤과 진행 단계 표시를 보여주고, 스트리밍 단계는 점진 텍스트와 깜빡이는 커서와 "중지" 버튼과 인용 스켈레톤을 보여주며, 완료 단계는 전체 답변과 인용 카드를 확정한다. 답변 영역에 `aria-live`를 둔다. 시안은 `design/rag-streaming`이다.
- rag 인용 카드는 근거 청크 본문(`citation.content`)을 화살표 토글로 펼쳐 왜 그 문서를 인용했는지 보인다(첫 인용은 기본 펼침).
- rag 인용 번호는 백엔드가 1부터 재정렬해 내려주므로 프론트는 그대로 표시한다(검색 순위 위치가 아니라 1, 2, 순).
- rag 답변은 마크다운으로 렌더한다. 스트리밍 중 누적 텍스트와 완료 답변이 같은 공유 뷰어(`components/drive/markdown-view.tsx`, `react-markdown`+`remark-gfm`)를 써서 렌더가 일관된다. 부분(미완성) 마크다운도 무난히 렌더해 스트리밍에 적합하다.
- 완료 답변의 인용 `[n]`은 `[n](#cite-n)` 링크로 전처리하고, 뷰어가 `a` 렌더를 오버라이드해 클릭 배지로 그린다(클릭 시 출처 이동). 스트리밍 중에는 인용이 확정 전이라 `[n]`을 평문으로 둔다.

### 3a. 공통 메타 (모든 검색 첨부)
- 총 응답 시간(`elapsed_ms`).
- 총 결과 개수(키워드/의미) 또는 총 인용 개수(rag). 키워드/의미는 문서 수·청크 수를 함께 표시한다.
- 키워드/의미 결과는 `documentId`로 그룹화해 문서당 1 카드로 렌더한다(헤더=현재 파일명(큰 제목)·ai 보정 제목(작은 제목, 있을 때)·최고 score·청크 수). 그룹화·정렬(그룹=최고 score, 청크=score desc)은 프론트에서 수행한다(검색 API는 청크 평면 반환). rag 인용 카드도 동일하게 큰 제목=현재 파일명, 작은 제목=ai 보정 제목으로 표시한다.
- 카드 내 청크는 화살표 토글 행 목록으로 렌더한다. 각 행 헤더는 chunk_id·score이고, 행을 클릭하면 본문이 펼침·접힘한다(첫 청크는 기본 펼침). 청크가 2개 이상이면 "더보기/접기"로 첫 청크 외 나머지 행을 노출한다.
- 키워드 모드는 청크 본문에서 질의 일치 부분을 하이라이트한다. 문서 keywords는 키워드·의미 모드 공통으로 컨셉 해시태그로 표시한다(검색 응답에 포함, 문서 단위. 청크 단위 컨셉은 백엔드 미제공이라 문서 단위로 근사).

### 3b. 결과 row 액션
- 결과 row: 단일 클릭=선택(인스펙터 토글), 더블 클릭/눈 버튼=인스펙터 열기(frontend.md §5).
- 행 "⋯" 드롭다운과 우클릭 컨텍스트 메뉴: 다운로드, 해당 폴더로 이동, 삭제.
- "해당 폴더로 이동"은 그 문서의 폴더로 이동한 뒤 해당 문서를 선택한다(`folderHref(folderId, docId)`).
- rag 답변의 인용 `[n]` 클릭은 해당 출처로 이동한다.

## 4. 결과 화면 네비게이션
- 본문 상단 좌측, 화면 제목 옆에 뒤로가기 버튼을 둔다.
- 결과 화면은 URL(`/search?q=&mode=`)로 표현한다. 뒤로가기 버튼은 `router.back()`으로 직전 화면(조회 또는 다른 결과)으로 돌아간다.

## 5. 상태 관리
- SearchBar 입력값은 Zustand, 검색/답변 결과는 react-query로 둔다(경계는 frontend.md §4).
- 제출 질의와 모드, 결과 화면 표시 여부는 URL이 진실 소스다(`/search?q=&mode=`, frontend.md §8). Zustand에 결과 화면 상태를 따로 두지 않는다.
