# AI 산출물 & 계보(Lineage)

## 1. 기능 요구사항
- 요약/초안/보고서 AI 산출물 워크플로우 + 계보 메타데이터.
- 생성마다 provider/model을 스냅샷으로 기록한다.

## 2. 설계 결정
- 차트는 선언형 스펙으로 만들고 코드 실행은 하지 않는다.
- 산술 계산은 결정적 코드로 한다(LLM에 시키지 않는다).
- 계보는 행 단위 스냅샷, 인용은 번호↔청크 매핑으로 보존한다.

## 3. Summary 워크플로우
- 문서 길이에 따라 분기한다: 단순 1콜 / 청크별 요약 후 통합 / 섹션 그룹 재귀.
- 청크 미니요약과 문서 최종요약을 2단으로 저장하고 인용을 표기한다.

## 4. Draft 워크플로우
1. 개요 제안
2. 사용자 개요 편집
3. 섹션별 관련 청크 검색·생성(인용)
4. 조립·일관성 패스
- 템플릿(보고서/제안서/공문/메모)을 선택한다.

## 5. Report 워크플로우
1. 구조화 데이터 추출
2. 결정적 통계 계산
3. 차트 스펙 생성
4. 스펙 검증·수리
5. 렌더 + 서사(인용)

## 6. 계보 데이터 모델
- 한 생성이 헤드 한 행이고, 하위에 출처·프롬프트·차트가 연결된다.

## 7. 재현성
- seed·디코딩 파라미터·렌더된 프롬프트·모델 식별·provider를 저장해 동일 조건 재실행을 가능하게 한다.

## 8. 비동기 생성
- 생성은 수십 초~수 분 걸리므로 비동기로 처리한다.
- 요청 시 헤드를 `queued`로 먼저 기록하고 즉시 접수 응답하며, 워커가 이어받아 진행한다.
- 상태: `queued → running → succeeded | failed`.
- 진행 상태는 조회로 확인할 수 있다.

## 9. 산출물의 문서화 (1급 문서)
- AI 산출물은 일반 문서와 동일하게 `documents` 행 + 오브젝트로 저장돼 목록·검색·RAG 대상이 된다.
- 성공 시 산출물을 업로드하고 문서 행을 만들어 인제스트까지 수행하고, 결과 문서 id를 생성에 기록한다.
- "산출물 내역"은 원본 기준 목록으로, 출력 문서가 있는 생성만 보여준다. row 클릭 시 그 출력 문서로 이동한다.
- 출력 문서를 삭제하면 산출물 내역에서 자동으로 사라진다(계보 헤드 행은 감사 목적으로 유지).
- 산출물의 폴더 위치는 기본적으로 주 원본 문서와 같은 폴더(정책 추후 확정).
