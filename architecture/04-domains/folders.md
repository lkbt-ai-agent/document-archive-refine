# 폴더 관리

## 1. 기능 요구사항
- 폴더 생성/이름변경/이동/삭제
- 트리 조회

## 2. 설계 결정
- 채택: 인접 리스트(`parent_id`) + 재귀 CTE
  - 인접 리스트에서는 폴더 이동(MOVE)이 해당 폴더 한 행의 `parent_id`만 새 부모로 바꾸는 단일 UPDATE로 끝난다.
  - 하위 서브트리의 다른 행들은 건드릴 필요가 없다 (부모-자식 관계가 `parent_id` 한 컬럼에만 담겨 있어서).
  - 재귀 CTE(Common Table Expression): `WITH RECURSIVE` 구문으로 임시 결과 집합이 자기 자신을 반복 참조해 계층을 펼치는 SQL 표준 기능. 부모→자식→손자…를 한 쿼리로 따라가 서브트리 전체를 조회한다.
  - 재귀 CTE는 원격 PostgreSQL의 기본 기능이라 추가 확장이 필요 없다.
- 기각: 머티리얼라이즈드 패스/ltree/네스티드 셋/클로저 테이블 — 서브트리 재작성·복잡도 부적합.

## 3. 데이터 모델 참조
폴더는 `archive.folders` 테이블에 저장한다. 테이블 DDL·제약조건·실제 쿼리(트리 조회·MOVE 사이클 검사)는 모두 `folders-schema.md`에 둔다.

## 4. 트리 조회
- 소유자의 전체 폴더를 재귀 CTE로 한 번에 평면 리스트로 조회한 뒤, 프론트가 `useMemo`로 트리를 구성한다.
- 트리가 매우 크면 한 폴더의 직속 자식만 가져오는 레벨별 lazy 조회로 전환한다.
- 실제 조회 쿼리는 `folders-schema.md` §4.

## 5. MOVE (재부모) + 사이클 방지
- 폴더를 옮기기 전에, 새 부모가 "옮길 폴더 자신의 후손" 인지 재귀 조회로 먼저 검사한다.
- 후손이면 트리에 사이클이 생기므로 이동을 거부한다(422).
- 후손이 아니면 그 폴더 한 행의 `parent_id`를 새 부모로 바꾸는 단일 UPDATE를 트랜잭션 안에서 수행한다.
- 실제 검사·이동 쿼리는 `folders-schema.md` §4.

## 6. 재귀 삭제
- 폴더를 삭제하면 하위 폴더·문서·청크가 DB에서 연쇄 삭제된다(연쇄 규칙은 `folders-schema.md` §2).
- MinIO 오브젝트는 연쇄 대상이 아니라, service가 삭제 대상 문서들의 `object_key`를 먼저 모은 뒤 DB 삭제 후 worker가 오브젝트를 별도로 삭제한다(document.md 정합).

## 7. API 계약
| 메서드 | 경로 | 설명 |
|---|---|---|
| GET | `/folders` | 소유자 트리(평면 리스트) |
| POST | `/folders` | 생성 `{parent_id?, name}` |
| PATCH | `/folders/{id}` | 이름변경 `{name}` / 이동 `{parent_id}` |
| DELETE | `/folders/{id}` | 재귀 삭제 |

에러: 형제 중복명 409, 사이클 이동 422, 권한 외 404.

## 8. 권한·검증
- 서버는 모든 폴더 쿼리에 `owner_id` 조건을 강제해, 사용자가 자기 소유 폴더만 보고 조작하도록 제한한다.
- 서버는 폴더 생성·이름변경 시 이름 길이와 금지문자를 검증한다.
- 루트 폴더는 `parent_id`가 NULL인 행으로 표현한다.
