# 폴더 관리

## 1. 기능 요구사항
- 폴더 생성/이름변경/이동/삭제
- 트리 조회

## 2. 설계 결정
- 이동(MOVE)은 폴더 한 행의 부모만 바꾸는 단일 갱신으로 끝난다.
- 인접 리스트 채택 근거와 기각한 대안은 `folders-schema.md` §5.

## 3. 데이터 모델 참조
- 폴더는 `archive.folders` 테이블에 저장한다.
- 스키마·제약·실 쿼리는 `folders-schema.md`.

## 4. 트리 조회
- 소유자의 전체 폴더를 한 번에 평면 리스트로 조회한 뒤, 프론트가 트리를 구성한다.
- 트리가 매우 크면 한 폴더의 직속 자식만 가져오는 레벨별 조회로 전환한다.

## 5. 이동 (재부모) + 사이클 방지
- 폴더를 옮기기 전에, 새 부모가 옮길 폴더 자신의 후손인지 먼저 검사한다.
- 후손이면 트리에 사이클이 생기므로 이동을 거부한다.
- 후손이 아니면 그 폴더의 부모를 새 부모로 바꾼다.

## 6. 재귀 삭제
- 폴더를 삭제하면 하위 폴더·문서·청크가 연쇄 삭제된다(연쇄 규칙은 `folders-schema.md` §2).
- MinIO 오브젝트는 연쇄 대상이 아니라, 삭제 대상 문서들의 키를 먼저 모은 뒤 별도로 삭제한다(document.md 정합).

## 7. 권한·검증
- 서버는 모든 폴더 쿼리에 소유자 조건을 강제해, 사용자가 자기 폴더만 보고 조작하도록 제한한다.
- 폴더 생성·이름변경 시 이름 길이와 금지문자를 검증한다.
- 루트 폴더는 부모가 없는 행으로 표현한다.
