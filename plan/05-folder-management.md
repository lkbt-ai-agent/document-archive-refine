## 목적
인접 리스트 기반 폴더 트리의 CRUD·MOVE·재귀 조회/삭제 설계를 정의한다.

## 지켜야 할 제약
- 원격 PostgreSQL에서 재귀 CTE 동작(추가 확장 불필요).

## 작성 단계 (= 아키텍처 문서 섹션)
- [ ] S1. **개요/범위** — Drive형 폴더 트리, 소유자 스코프.
- [ ] S2. **데이터 모델 참조** — `folders`(03 §2) 요약, 형제 유니크 제약, 인덱스.
- [ ] S3. **트리 조회** — 재귀 CTE로 평면 리스트 반환 → 프론트에서 트리 구성(10과 정합). 대규모 시 레벨별 lazy(`WHERE parent_id=:id`).
- [ ] S4. **CRUD API 계약** — 생성/이름변경/삭제/목록. 요청·응답 스키마, 상태코드, 에러(중복명 등).
- [ ] S5. **MOVE(재부모)** — 1행 update + **사이클 방지 검증**(자기 후손 아래로 이동 거부) 재귀 CTE SQL, 동시성/트랜잭션 처리.
- [ ] S6. **재귀 삭제** — `ON DELETE CASCADE`로 하위 폴더·문서 연쇄, 연계로 문서 오브젝트(MinIO)·청크·계보 정리 훅(06/03과 정합).
- [ ] S7. **권한·검증** — `owner_id` 강제, 입력 검증(이름 길이/문자), 루트(NULL parent) 처리.
